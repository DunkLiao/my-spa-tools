## 給 AI Agent 的任務

你是此儲存庫的前端開發者。請依照上方需求，在 `my-spa-tools` 專案中建立一個可實際使用的新網頁工具，並完成所有必要的入口與文件整合。全程使用繁體中文與臺灣常用詞彙。

### 一、先了解專案，再選擇實作方式

1. 閱讀根目錄 `AGENTS.md`、`README.md`、`index.html`，並確認目前工作樹狀態。這些檔案是專案慣例與入口、文件整合的依據。
2. 檢查 `specs/` 中現有規格，以及所選分類內最接近本工具的頁面；需要時再參考 `agent/prompt-studio/` 或其他相關工具。比較它們的操作流程、頁面結構、資料保存、匯入匯出、外部相依與「回入口」實作。不可假設舊工具未列出的能力已存在。
3. 專案目前有九個固定分類：`agent/`、`finance/`、`sql/`、`data/`、`docs/`、`design/`、`diagram/`、`music/`、`social/`。工具頁面位於 `<分類>/<工具資料夾>/<入口檔名>.html`，深度固定為兩層。
4. 除非需求或既有規格明確要求不同做法，新工具使用單一靜態 HTML 檔，內含 CSS 與原生 JavaScript；免建置、無後端、無上傳流程，可由靜態伺服器提供。不要加入 `package.json`、打包器、框架或建置流程。若拆分檔案或引入函式庫確有必要，先說明原因，並在 README 標示 CDN／檔案相依與離線限制。
5. 先確認需求足以實作。若缺少的資訊會改變主要流程、計算結果、資料安全或交付範圍，先用精簡問題詢問；可安全推定的細節，列明採用的假設後繼續。不可自行捏造監理規定、業務政策、計算公式或使用者資料。

### 二、規格與範圍

- 若交付範圍包含「規格與實作」，先將本工具規格新增至 `specs/`，再依規格實作。規格至少描述：目標與成功標準、使用者與情境、範圍／不做項目、主要流程、頁面與狀態、輸入輸出、資料模型與保存方式、驗收條件、外部相依及已知限制。
- 將必須完成的內容與未來想法分開。沒有列入必要功能的能力，不要擅自擴大範圍。
- 若功能含計算或規則判定，先寫清楚公式、邊界條件、四捨五入及缺漏值處理；用需求提供的案例核對結果。規則尚未提供時，將其做成明確可編輯設定或先詢問，不要用虛構預設值冒充正式規則。
- 操作流程要涵蓋第一次使用、空資料、正常完成、輸入錯誤、無結果、保存失敗與重新載入等狀態。若資料會被修改或刪除，提供清楚的操作回饋；不可讓成功訊息掩蓋失敗。

### 三、實作品質

- 讓需求中的主要工作能在介面中完整完成；不要只做靜態展示、按鈕空殼或預設資料模擬。
- 使用語意化 HTML、清楚標籤與欄位錯誤提示；支援鍵盤操作、可見焦點、合理色彩對比與窄螢幕版面。避免以顏色作為唯一狀態提示。
- 預設採本機瀏覽器處理資料。選擇最符合用途的保存方式：一次性計算可用頁面記憶體；少量設定可用 `localStorage`；結構化、多筆或含檔案的資料優先考慮 IndexedDB。不得靜默改用較弱的保存方式。說明清除瀏覽器資料的影響，以及 `file://` 和本機 HTTP 環境可能有的差異。
- 若有匯入功能，檢查格式、必要欄位、型別、重複鍵及資料量；在寫入前提供可理解的錯誤或確認，且無效檔案不可破壞既有資料。若有匯出功能，確認內容完整、檔名與副檔名正確，並處理空資料。
- 任何使用者文字都視為不可信輸入。動態顯示文字時避免直接串接未跳脫的 HTML；避免 `eval`、任意程式碼執行與不必要的權限要求。
- 避免不必要的外部資源。使用 CDN 時，記錄函式庫用途、版本與網路需求；核心功能應明確處理相依載入失敗的情況。不得新增伺服器端處理或上傳使用者檔案。
- 不要在介面或程式中加入不必要的開發說明、假資料敘述或未實作的承諾；範例資料須清楚標示，且不應被誤認為使用者正式資料。

### 四、必須整合的專案慣例

1. **固定回入口按鈕：**在入口 HTML 的 `</body>` 前放置 `AGENTS.md` 所規定的完整標準片段。必須使用 `id="hf-home-entry"`、`href="../../index.html"`、固定左下角、自包含 inline `<style>`，保留列印隱藏規則。若左下角已有固定控制項，依 `AGENTS.md` 調整位置但維持 id 與既有視覺。請複製 `AGENTS.md` 的原始片段，不要自行改寫標籤、文字或樣式。
2. **更新入口大廳：**在根目錄 `index.html` 的正確分類區塊新增 `.card`，包含相對 `href`、圖示、工具名稱、一句用途、`離線可用` 或 `需 CDN` 標籤，以及搜尋用的 `data-title`／`data-tags`。維持分類錨點、分類區塊和篩選 chip 的 `data-category`／`data-filter` 一致；更新分類工具數量或統計（若入口有此資訊）。
3. **更新使用手冊：**在根目錄 `README.md` 更新工具總覽、快速開始及對應分類的操作章節。寫出實際操作步驟、資料保存方式、離線／CDN 限制、匯入匯出與重要注意事項；僅描述已完成的功能。
4. **檔案格式：**新增或修改的文字檔使用 UTF-8（無 BOM）與 LF 換行；保留 `.gitattributes` 規範。不要格式化或改寫與本任務無關的檔案。

### 五、完成前檢查與回報

依照根目錄 `AGENTS.md` 的驗證清單檢查本次變更，並回報實際執行的項目與結果。至少確認：

- 新工具檔案及入口相對路徑正確，能由專案根目錄啟動的本機 HTTP 伺服器開啟。
- 「回入口」按鈕存在，連結回到根目錄 `index.html`。
- `index.html` 新卡片與分類／搜尋篩選資料正確；README 與入口的本次新增相對連結都指向存在的檔案。
- 新增或修改檔案為 UTF-8 無 BOM、LF；執行 `git diff --check` 並回報結果。
- 對照需求逐項列出已完成與未完成項目；未實際操作瀏覽器驗證的功能，不可宣稱已通過瀏覽器測試。

最終回報請用繁體中文，簡述新增／修改檔案、主要功能、文件與入口整合情況、驗證結果及尚存限制。若遇到阻礙，指出具體檔案、錯誤與可繼續處理的部分，不要只回覆概括性結論。
