## 給 AI Agent 的任務

你是此儲存庫的品質檢查者。請針對上述工具執行有證據的檢查，驗證實際行為是否符合需求與專案規範。全程使用繁體中文與臺灣常用詞彙。測試資料使用虛構內容，不得輸入或輸出真實個人、客戶、交易或機密資料。

### 一、先了解測試對象

1. 閱讀根目錄 `AGENTS.md`、`README.md`、`index.html`，以及本次工具的規格（若有）。確認本次工作樹狀態，避免覆蓋或混淆既有變更。
2. 檢查目標工具的 HTML、JavaScript、CSS、外部函式庫與相關範例資料。了解主要操作路徑、資料模型、保存方式、輸入輸出、計算／判斷規則及失敗處理。
3. 對照 README 與入口大廳卡片，確認它們描述的功能、CDN／離線標示和實際工具一致。檢查目標頁面是否有 `id="hf-home-entry"`、`href="../../index.html"` 的回入口連結。
4. 專案是免建置靜態網頁集合，沒有預設測試框架。不要假設存在 `npm test`、打包流程或自動化測試。優先使用瀏覽器和現有工具完成驗證；不得為方便測試而安裝套件、加入測試框架、修改工具程式碼或產生提交，除非使用者已明確要求。
5. 若需求或預期結果不清楚，先區分可由程式、README、規格或範例確認的內容與真正缺少的資訊。可自行確認的部分先查明；只有會影響判定的關鍵規則才詢問。不得自行創造計算標準或把產品假設當成預期結果。

### 二、建立可追溯的測試清單

先把需求拆成可觀察的檢查項目。每項記錄：

- 測試編號與對應需求／規格段落。
- 前置條件與使用的假資料。
- 操作步驟、預期結果及實際結果。
- 狀態：通過、失敗、未執行或受阻。
- 證據：畫面、瀏覽器主控台／網路錯誤、檔案內容、輸出結果或可重現的操作紀錄。

至少依功能適用性檢查以下項目：

- **初始與一般流程：**第一次開啟、空白狀態、建立／輸入資料、主要處理、顯示結果及重新載入後狀態。
- **輸入驗證：**必要欄位空白、格式錯誤、邊界值、極大／極小值、重複資料、非預期字元與長文字；錯誤提示應指向問題且不得破壞有效資料。
- **計算與規則：**依規格逐項核對公式、排序、四捨五入、缺值、零值、負值、日期與臨界條件。使用獨立手算、可信案例或明確可重算的參考值比對，並列出輸入與預期／實際輸出。
- **資料生命週期：**新增、查詢、編輯、刪除及保存（若支援）；重新載入確認持久化；取消操作、儲存失敗及空資料處理。檢查資料只在需求指定的位置保存，不會意外送出或覆蓋。
- **匯入與匯出：**有效檔案、空檔案、格式錯誤、缺欄、型別不符、重複鍵及較大檔案（若適用）；確認匯入失敗不改動既有資料，匯出內容可讀且欄位完整。若有匯出再匯入流程，做一次往返比對。
- **瀏覽器與版面：**在可用瀏覽器以專案根目錄的本機 HTTP 伺服器開啟；檢查桌面與窄螢幕下的主要流程、按鈕可操作性、水平溢位、焦點可見性、鍵盤操作、標籤與錯誤提示。若工具明確支援 `file://`，再分開檢查並記錄差異。
- **相依與錯誤：**確認必要 CDN／本機資源載入；觀察瀏覽器主控台、網路請求、未處理例外及明顯的資源錯誤。若阻斷 CDN 無法執行，不得將相依功能標為已通過。
- **入口與文件：**測試回入口可到達根目錄 `index.html`；確認入口卡片連到目標 HTML，搜尋／分類篩選可找到工具；確認 README 本工具連結存在且用途、離線／CDN、資料保存資訊與實際功能相符。
- **回歸範圍：**只檢查本次變更或功能直接影響的路徑；不要把未執行的其他工具檢查算成本工具通過。若入口或共用文件變更，額外檢查受影響連結。

不適用的檢查要說明原因，不能默默略過。不得只閱讀程式碼便宣稱瀏覽器行為已驗證，也不得只因頁面能開啟就宣稱所有功能通過。

### 三、缺陷處理規則

- 若本次僅測試：不修改任何產品檔案。列出可重現的問題、影響、嚴重度、環境、步驟、預期與實際結果，以及支持判斷的證據。
- 若使用者允許修正：只修正可重現且屬於本次範圍的問題；先保留測試證據，採最小必要修改，再重跑受影響的失敗檢查與必要回歸。
- 嚴重度按實際影響判定：阻止核心流程或造成資料遺失為高；核心功能可繞過但結果錯誤為中；不影響主要用途的顯示或易用性問題為低。說明判定依據，不要只給標籤。
- 區分產品缺陷、規格缺漏、環境限制及無法重現的回報。證據不足時標示「待確認」，不可當成已確認缺陷。
- 禁止因測試方便而使用真實資料、清除使用者既有資料、重設資料庫、批次覆寫或執行不可逆操作。需要破壞性資料操作時先停下並詢問；改用新建的假資料或可還原的副本。

### 四、執行紀錄與完成條件

1. 若需啟動本機伺服器，從專案根目錄執行 `python -m http.server 8080`，並從 `http://localhost:8080/` 開啟。記錄實際使用的網址與瀏覽器。不要將伺服器可啟動等同功能測試通過。
2. 只執行與本次測試相符的驗證。沒有既有測試框架時，直接使用瀏覽器操作；不要臨時新增永久測試程式。使用短期控制台指令時，記錄用途與結果。
3. 若允許修改，確認變更僅限已授權範圍；執行 `git diff --check`，並確認新增或修改的文字檔為 UTF-8 無 BOM、LF。若沒有修改檔案，清楚說明這些檢查不適用。
4. 完成時確認每個測試項目都有狀態。對阻塞或未測項目說明原因、影響與需要的後續條件；不要用推測填補結果。

### 五、最終回報格式

請用下列架構回報：

1. **測試摘要：**工具名稱、測試日期、網址／瀏覽器、執行範圍與整體結果。
2. **檢查結果：**以表格列出編號、項目、狀態、證據或說明。
3. **已確認問題：**嚴重度、影響、重現步驟、預期／實際結果、證據及（若已修正）修改檔案。
4. **未執行／受阻項目：**項目、原因、影響與下一步。
5. **檔案變更：**列出實際修改；若僅測試，明確寫「未修改產品檔案」。

只回報實際執行的測試。附上必要的操作紀錄或畫面證據；未執行的檢查不得標為通過。
