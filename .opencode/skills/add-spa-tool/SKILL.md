# Add SPA Tool

將一個新的單頁網頁工具（HTML）分類並完整設定進 `my-spa-tools` 專案，使其出現在入口大廳、使用手冊與規範中，並符合專案慣例。

## 開始前

**先閱讀專案根目錄的 `AGENTS.md`**，它是資料夾分類、命名慣例、「回入口」按鈕標準片段與驗證清單的唯一權威來源。本 skill 的步驟若與 `AGENTS.md` 衝突，以 `AGENTS.md` 為準。

固定事實：

- 分類層固定六類：`agent/`、`finance/`、`sql/`、`data/`、`docs/`、`design/`。
- 每個工具自成一層子資料夾：`<類別>/<工具>/<檔名>.html`。
- **所有工具頁面都在根目錄下兩層**，因此「回入口」連結固定為 `../../index.html`。
- 檔名與資料夾名稱使用小寫 kebab-case。
- 檔案一律 UTF-8（無 BOM）＋ LF。
- 入口大廳 `index.html` 為單檔、零 CDN 相依。

## 工作流程

### 1. 讀懂工具

讀取使用者提供的 HTML，判斷：

- **用途／一句話說明**：從 `<title>`、`<h1>` 與主要區塊整理。
- **分類歸屬**：屬於既有六類之一，還是需要新分類。
- **外部相依**：是否有 `cdn.`、`googleapis`、`unpkg` 等，決定標籤為「需 CDN」或「離線可用」。
- **資料保存**：搜尋 `indexedDB`、`localStorage` 或皆無（頁面記憶體），以及資料庫名稱。

### 2. 決定分類與命名（不確定就問）

- 若工具不屬於現有分類，**先詢問使用者**：要新增哪個分類名稱、是否要變更分類層（新增分類會影響 `AGENTS.md` 與入口大廳 chip）。不要擅自新增分類。
- 與使用者確認目標資料夾與檔名（建議 `<類別>/<工具>/<工具>.html`，檔名去掉 `_with_indexeddb` 之類的實作細節後綴）。

### 3. 搬移與改名

```powershell
New-Item -ItemType Directory -Force <類別>\<工具> | Out-Null
Move-Item -LiteralPath "<原檔.html>" -Destination "<類別>\<工具>\<工具>.html"
git add "<類別>\<工具>\<工具>.html"
```

若檔案已被 Git 追蹤，改用 `git mv` 保留歷史。

### 4. 加入「回入口」按鈕

**使用 `AGENTS.md` 中的標準片段**（不要自行改寫樣式或 id）。將片段插入工具頁面**最後一個** `</body>` 之前：

- 工具檔通常包含 JS 匯出樣板字串（例如 `...</body></html>\`;`），要確認插入的是檔案結尾那個真正的 `</body>`，而非樣板字串內的那個。
- 本專案檔案為 LF，使用 `</body>\n</html>` 作為唯一比對錨點即可避開樣板字串。

### 5. 更新入口大廳 `index.html`

- 若為新分類：新增一個篩選 chip（`data-filter="<類別>"`），並在 `<main>` 內新增一個 `<section class="category" data-category="<類別>">` 與標題。
- 在對應分類區塊新增一張 `.card`：`href` 相對路徑、`data-title`、`data-tags`（供搜尋）、`.icon`、名稱、一句話說明、`離線可用`／`需 CDN` 標籤、`開啟工具 →`。
- 更新計數文字：`<header>` 的 lede（「N 個…」）、`<meta name="description">`、頁尾「共 N 個工具」。
- 入口大廳**不得**加入「回入口」按鈕，也**不得**引入 CDN。

### 6. 更新 `README.md`

依序更新：

- 開頭摘要的工具數與類型敘述。
- `## 目錄` 新增該工具章節連結。
- `## 快速開始` 的入口清單新增一行。
- `## 專案結構` 的樹狀圖與「N 類歸類」敘述。
- `## 整體使用流程` 的 mermaid（新增一個工具類型分支）。
- `## 工具總覽` 表格新增一列（工具／入口／用途／資料保存）。
- 新增該工具的 `## <工具名>` 章節（操作步驟、匯出/保存、注意事項、mermaid）。
- `## 資料保存、匯出與隱私` 的 mermaid 與清單。
- `## 技術棧與離線範圍` 的外部資源清單與敘述。
- `## 維護者驗證` 的入口數與驗證項目。

### 7. 視情況更新 `AGENTS.md`

只有在**分類層變動**（新增／移除分類）或工具總數變動時才更新：結構樹、分類數敘述、驗證清單的工具數。

### 8. 驗證

執行隨附腳本（路徑相對於本 `SKILL.md`）：

```powershell
powershell -ExecutionPolicy Bypass -File .opencode/skills/add-spa-tool/scripts/verify.ps1
```

腳本會檢查：每個工具頁都有「回入口」且 `../../index.html` 可解析、入口頁沒有按鈕、`README.md` 與 `index.html` 的相對連結都存在、各 HTML 的編碼（無 BOM）與換行（LF）。全部通過才視為完成。

`git diff --check` 若出現行尾空白警告，先判斷是否為**匯入檔案既有的**內容；不要為了消除警告而改動工具本體程式碼，除非使用者要求。

## 邊界

- 除了「回入口」片段與必要的路徑修正，**不要改寫工具本體程式碼**。
- 不要在各工具子資料夾建立 README；單一工具說明一律併入根目錄 `README.md`。
- 不要新增後端或上傳流程；所有資料處理維持在瀏覽器端。
- 不要未經詢問就新增分類或變更既有分類名稱。
